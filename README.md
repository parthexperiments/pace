# Pace — AI Running Coach

I built Pace because I was training for my first half marathon
and every running app was giving me the same useless number:
average pace. That number includes every traffic light, every
phone check, every time I stopped to cross a road. It tells
me nothing about how I actually ran.

Pace connects to Strava, pulls the raw stream data from each
run, and breaks it down into what actually happened — how fast
I was moving when I was moving, what percentage of the run I
was actually running vs walking vs stopped, and how each
kilometer compared to my goal pace. Then it gives me one clear
thing to work on before my next run.

## The Problem I Was Solving

When I started training seriously I had two problems:

1. I didn't know if I was actually improving or just running
   more kilometers at the same quality.
2. I didn't know what to change from one run to the next.
   Every app told me what happened. None of them told me
   what to do about it.

Strava shows elapsed pace — which is misleading. A runner who
stops for 10 minutes across an 18km run sees a slow average
and thinks they're unfit. Their actual running pace might be
close to their goal. The gap is in non-running time, not
running ability. Pace surfaces that distinction.

## What Pace Does

### Run Analysis
Every run gets broken down into:
- Overall pace (what actually happened across the full run)
- Moving pace (pace when actually running — shown only when
  stopping is significant)
- Running / Walking / Stopped distribution as percentages
- Kilometer-by-kilometer splits colour coded against goal pace
- Run type classification: Long Run, Tempo, Easy, Short,
  Race Effort — detected automatically from distance and
  pace relative to your goal

The AI coach then finds what matters most in that specific
run. Not a fixed checklist. It looks at the numbers and
identifies the most significant pattern — whether that's
a pace fade in the final third, inconsistent splits, high
walking percentage, or a specific km that stood out.

### Progressive Coaching
This is the part that makes it different from a one-off
analysis tool. Every run of the same type (long, tempo,
easy etc.) is compared to the previous run of that type.
The coach explicitly assesses whether the recommendation
from last time was followed and whether it made a difference.

Example: Last long run the coach said "start your next
long run 15 seconds per km slower for the first 5km."
Next long run — did the pace fade reduce? Did the running
percentage improve? The coach calls it out directly.

### Weekly Training Plan
Generated by Claude based on:
- Your goal distance and target pace
- Weeks remaining to your goal date
- Your last 4 weeks of actual training data
- Your available training days

Phases: Base building -> Build -> Peak -> Taper. The plan
adapts to where you are in training, not a generic
12-week template.

Strength sessions included on non-running days with
4-5 specific exercises scaled to training phase —
lighter during taper, heavier during build.

### Pre-Run Brief
Generated each run morning based on today's planned
session and patterns from your last 3 runs. Includes:
- A focus cue that references a specific pattern
  (e.g. "your first km averages 30s faster than the
  rest — start deliberately slower today")
- Pacing strategy with split targets
- 5 dynamic warm-up exercises specific to run type
- A mental cue for the run

### Dashboard
State-aware home screen that knows what kind of day it is:
- Rest day: shows last run snapshot, mobility routine,
  days to goal
- Run day pre-run: shows today's planned session and
  pre-run brief prominently
- Run day post-run: shows run analysis card with key
  insight and link to full analysis
- Auto-syncs new runs from Strava in the background —
  no manual sync button

### Progress Tracker
Charts across all your historical runs:
- Running time % trend per run
- Pace gap trend (moving vs overall — shown only when
  stopping is significant)
- Moving pace trend with goal pace reference line
- Longest run each week
- Weekly kilometres
- Milestone feed: first run above 80% running time,
  fastest moving pace, longest run, biggest week

## Design Decisions Worth Explaining

**Overall pace is the primary metric, not moving pace.**
Moving pace is a diagnostic tool shown only when stopped
percentage exceeds 10% of elapsed time. For runners who
don't stop significantly, moving pace and overall pace
are nearly identical — showing both is noise.

**Speed distribution uses plain language.**
Running / Walking / Stopped. Not the technical terms
the backend uses. Walking is 2-6 km/h. Stopped is below
2 km/h. Running is above 6 km/h.

**Run type is deterministic, not AI-generated.**
The app classifies run type from distance and pace
relative to your goal — not from Claude. This matters
because category-level progress comparison only works
if the same kind of run gets tagged the same way
every time.

**Historical runs are preprocessed on first login,
not analysed.**
Preprocessing (the data pipeline) takes 2-3 seconds
for 30 runs. Full Claude analysis happens lazily —
only when you open a specific run's analysis page.
This keeps onboarding fast.

**Previous run summaries are compressed, not full.**
When analysing a run, Claude receives a compact summary
of the previous run of the same type — all insights,
the recommendation, and whether it was followed. Not
the full analysis prose. This keeps token costs low
while preserving the coaching context that matters.

**Claude never sees raw Strava streams.**
Raw streams can contain 6,000-9,000 data points per run.
The preprocessing pipeline converts this into ~700 tokens
of structured metrics before anything touches the AI.
Faster, cheaper, and more consistent outputs.

## Tech Stack

- Next.js 14 App Router
- TypeScript
- Tailwind CSS
- Supabase (PostgreSQL)
- NextAuth v4 (Strava OAuth)
- Anthropic Claude API (claude-sonnet-4-5)
- Strava API v3
- Recharts

## Local Setup

### 1. Install dependencies
```bash
npm install
```

### 2. Add environment variables
Create `.env.local`:
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
STRAVA_CLIENT_ID=
STRAVA_CLIENT_SECRET=
NEXTAUTH_SECRET=
NEXTAUTH_URL=http://localhost:3000
ANTHROPIC_API_KEY=

### 3. Run locally
```bash
npm run dev
```

Open `http://localhost:3000`

## Notes

- Coaching is always grounded in specific numbers from
  the run data. No generic advice.
- AI outputs are cached in the database. Never
  regenerated on page load.
- The app is designed for one goal at a time. Every
  feature is built around a specific race target —
  not general fitness tracking.
